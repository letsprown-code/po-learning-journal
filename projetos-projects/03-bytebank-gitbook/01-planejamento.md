# Etapa 1 do DDLC · Análise e planejamento

> Documento de estudo. A Bytebank é fictícia. Estrutura baseada no modelo de planejamento do curso.

## 1. Contexto do projeto

A Bytebank passou por um **rebranding** da marca e do aplicativo, com uma nova experiência para os clientes. Os materiais de apoio ficaram desatualizados, então é preciso planejar novas documentações para essas pessoas.

Este projeto também aproveita o que foi escrito no [Projeto 02](../02-bytebank-docs/README.md) (Caixinhas), que precisará ser revisado para a nova marca.

## 2. Público

Pessoas físicas clientes da Bytebank, que **não têm necessariamente conhecimento técnico**. Por isso, conceitos do mercado financeiro podem precisar de contexto ou de um glossário.

## 3. Conhecimento técnico

Conhecimento básico de finanças.

## 4. Necessidades apontadas pelos SMEs

*(Simulado, como no curso.)*

- Contextualizar **todos os serviços** da Bytebank.
- Dar destaque ao serviço de **Investimentos**, que acabou de ser lançado.
- Atualizar as documentações das **Caixinhas** para a nova marca.

## 5. Como vou levantar as informações

| Fonte | O que fazer |
|---|---|
| Testes no aplicativo | Abrir o app e percorrer cada fluxo que vai ser documentado |
| Demos com o time de desenvolvimento | Pedir uma demonstração do serviço de Investimentos e **gravar** a reunião para consulta |
| SMEs (especialistas no assunto) | Conversar com quem conhece Investimentos e Caixinhas para entender regras e contexto |
| Documentação existente | Usar o [inventário do Projeto 02](../02-bytebank-docs/plano-de-documentacao.md) como ponto de partida |

## 6. Ferramentas necessárias

| Para quê | Ferramenta |
|---|---|
| Capturas de tela | Ferramenta de print do próprio sistema |
| Diagramas | Mermaid (alinhar com UX/design se precisar de imagens elaboradas) |
| Tradução | Não precisa por enquanto: a documentação é só em português |
| Publicação | **Gitbook** (plano gratuito) |
| Criação de vídeos | A definir, se os tutoriais precisarem de vídeo |

## 7. Pessoas envolvidas e prazos

Se UX ou design ajudarem com imagens e diagramas, alinhar **quem entrega o quê** antes de fechar os prazos, porque essas entregas entram no cronograma.
