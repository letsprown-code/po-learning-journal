# Etapa 6 do DDLC (continuação) · Métricas de sucesso

> Documento de estudo. A Bytebank é fictícia. Segue os vídeos da Aula 05 do curso.

## 1. Resultado esperado → dados

Caminho da aula: primeiro o **resultado** que a documentação deve trazer, depois os **dados** que mostram se ele está acontecendo.

| Resultado esperado | Dados para acompanhar | Por quê |
|---|---|---|
| **Aumentar a adoção dos serviços**, principalmente o de Investimentos, depois do rebranding | Número de clientes usando Investimentos, cruzado com a data de publicação da página; taxa de retenção | A métrica da documentação costuma ser indireta: aparece no cruzamento com dados do produto |
| **Diminuir casos de suporte** sobre o app novo | Número de tickets abertos sobre Investimentos; número de acessos à página; percentual de satisfação | Se os acessos sobem e os tickets caem, é um sinal de que a documentação ajuda |

## 2. Métricas por grupo

| Grupo | Métricas | Como obter neste projeto (GitHub) |
|---|---|---|
| **Da documentação** | Acessos, páginas mais e menos visitadas, percentual de satisfação | O curso cita a integração com o Google Analytics quando a documentação vira site. No GitHub, isso depende de publicar como site; fica como próximo passo |
| **Da pessoa usuária** | Comentários de feedback, pesquisas, testes de usabilidade | Link para um formulário de feedback no fim de cada página (como a VTEX); issues no GitHub para comentários; testes com o time de UX |

## 3. Fontes de dados (segundo a aula)

- Formulários de feedback.
- Ferramentas de métricas (no curso: Insights do Gitbook e Google Analytics).
- Entrevistas com pessoas usuárias, junto com UX.
- Time de dados ou BI, se houver.

## 4. Como usar os números

- Página com avaliação negativa → priorizar melhoria, conforme o feedback.
- Muitos acessos e poucos feedbacks → pouco engajamento; pensar em como estimular o feedback.
- Tudo volta para o **planejamento** do próximo ciclo do DDLC. Se a forma de medir não estiver funcionando, recalcular a rota.
